# 홍보물 속 "6-에이전트 매매 파이프라인" 기술 해설

밈코인(주로 Solana DEX) 자동매매 홍보물이 반복해서 쓰는 구조다. 2026-11 "Grok Bot Terminal" 사례 화면 기준으로 정리했다. 각 단계가 **실제로 해 주는 일**과 **해 주지 못하는 일**을 구분하는 것이 목적이다.

## 0. 전체 흐름

```
SCOUT(발굴) → FILTER(하드 룰 8개, 하나라도 실패 시 탈락) → ANALYST(0~100점, 70+만 통과)
  → EXECUTOR(잔고 최대 8% 진입) ↔ RISK(진입 전 -6% 손절, +12% 이후 추적 손절) → LOGGER(전부 기록)
"one prompt · six agents · hard handoffs · no coin picked by hand"
```
"hard handoff" = 각 단계는 자기 일만 하고, 통과한 것만 다음 단계로 넘긴다(파이프라인/퍼널 구조). 설계 개념으로는 정상적이다.

## 1. SCOUT — 신규 페어 발굴
- 조건: 생성 30분~72시간, 시가총액 $30만~$2,000만, 데이터 출처 DexScreener.
- **해 주는 일:** 관심 대상을 좁힌다. 공개 API로 누구나 구현 가능.
- **못 하는 일:** 이 구간은 러그·펌프 앤 덤프가 가장 많은 구간이다. 발굴 자체는 엣지가 아니다(같은 API를 수천 개 봇이 본다).

## 2. FILTER — 하드 룰 8개 (화면상 "~91% 탈락")
| 규칙 | 의미 | 한계 |
|---|---|---|
| mint / freeze revoked | 추가 발행·계정 동결 권한 포기 | 기본 위생일 뿐 |
| LP burned or locked | 유동성 회수(러그) 차단 | 락 기간 만료, 다른 풀로 회피 가능 |
| liquidity ≥ $40k | 최소 유동성 | $4만 풀에 진입하면 큰 슬리피지 |
| 1h volume ≥ $50k | 최근 거래 활발 | 워시 트레이딩(자전거래)으로 쉽게 부풀림 |
| top 10 holders ≤ 25% | 물량 집중 방지 | 지갑을 쪼개면 우회 |
| dev ≤ 3% · no rug past | 개발자 보유량·과거 러그 이력 | 새 지갑으로 우회 |
| bundled launch ≤ 10% | 첫 블록 번들 매수 비중 | 탐지 방식에 따라 누락 |
| 1h pump ≤ 80% | 이미 급등한 것 추격 방지 | — |

**결론:** 공개된 "러그 체크리스트"다. **손실 확률을 줄이는 방어막**이지 수익 원천이 아니다.

## 3. ANALYST — 점수 0~100 (70+ 통과)
- 항목: momentum, unique buyers, buy/sell ratio, holder growth, liquidity/mcap, smart wallets.
- **해 주는 일:** 여러 신호를 한 숫자로 정리.
- **못 하는 일:** 가중치·임계값 근거(백테스트, 표본 수, 기간)가 없으면 임의의 점수다. 모멘텀·스마트 월렛 추종은 경쟁이 가장 치열해 신호가 보일 때는 이미 늦은 경우가 많다.

## 4. EXECUTOR — 잔고 최대 8% 진입
- 포지션 사이징은 좋은 습관. 그러나 **8% 진입이면 큰 수익을 내기 어렵다** — 264배를 만들려면 +100% 거래를 손실 없이 약 74번 연속(비용 2% 가정) 이겨야 한다(`scripts/claim_math.py`).
- 실제 체결 비용: DEX 수수료, 슬리피지(얇은 풀), 우선순위 수수료, 샌드위치(MEV) 공격.

## 5. RISK — 진입 전 -6% 손절, +12% 이후 추적 손절
- 개념은 정석(진입 전 손절가 설정, 수익 구간에서 추적 손절).
- **한계:** 온체인 DEX에는 거래소식 보장 손절 주문이 없다. 봇이 가격을 감시하다 시장가로 파는 방식이라 급락·러그·허니팟(매도 불가/고율 매도세)에서는 -6%가 -50~-100%로 미끄러진다.

## 6. LOGGER — 모든 탈락과 거래 기록
- 유일하게 "거짓말할 수 없게" 만드는 부품. **로그 원본(트랜잭션 해시 포함)을 공개하지 않는 홍보물은 로거를 자랑하면서 증거는 숨기는 것.**

## 7. "one prompt" 주장과 직접 만들고 싶을 때
- LLM(Grok 등)에게 프롬프트 하나를 붙여 넣는다고 매매가 되지 않는다. 실제로는 ① 데이터 수집 코드, ② 지갑 개인 키를 가진 실행 코드, ③ 상시 가동 서버가 필요하다. "폰 충전기에 꽂고 잤다"는 연출과 맞지 않는다 — 누군가의 서버/봇에 키나 자금을 맡기는 구조가 숨어 있다.
- 사용자가 학습 목적으로 만들고 싶다면 이 스킬은 **모의매매(paper)와 백테스트까지만** 돕는다:
  - 공개 읽기 전용 데이터(예: DexScreener 공개 API)로 SCOUT·FILTER·ANALYST를 구현하고, 체결은 가상 장부로 기록.
  - 가상 체결에 슬리피지·수수료·지연을 보수적으로 넣는다(유동성 대비 주문 크기에 비례).
  - 최소 수백 건 이상 기록한 뒤 승률·평균 손익비·최대 낙폭·손절 미끄러짐 분포를 본다.
  - 실자금 연결, 개인 키 처리 코드는 작성하지 않으며, 그 결정은 사용자 본인 책임임을 명시한다.
